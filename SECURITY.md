# Security policy

## Supported version

Only the latest commit on `main` is maintained.

## Reporting

Do not paste a suspected secret, personal record or exploitable detail into a public issue. Open a minimal issue that identifies only the affected path and asks the maintainer to establish a private channel. If GitHub private vulnerability reporting is available in the repository's **Security** tab, prefer it.

The public mirror intentionally contains no production credentials, databases or deployment access. If sensitive material is ever committed, the response must include removing it from the public tree and history, revoking or rotating the underlying credential when applicable, and documenting the remediation without reproducing the secret.
